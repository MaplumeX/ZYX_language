## SKILL.md 最需要补充或澄清的点

1. **保留 N 位小数**（影响最大）。文档只给了 `round(x * 10) / 10.0`，但它的结果是 float，打印出来是 `20.0`，不是 `20.00`，而且整数值会只剩一位小数。表格、金额这类场景都需要定宽的小数。建议在"输出格式"一节给出一个现成的写法：
   ```zyx
   fn fmt2(v) {            # v >= 0
       let c = round(v * 100)
       let frac = pad_left(c % 100, 2, "0")   # 不能直接写进插值：插值里不能有字符串字面量 "0"
       "{c / 100}.{frac}"
   }
   ```
   最直观的写法 `"{c / 100}.{pad_left(c % 100, 2, "0")}"` 正好踩中第 8 条，所以这个惯用法值得直接写进文档。另外要提醒：负数需要单独处理，`round(1.005 * 100)` 这类浮点误差也要注意。
2. **`float(x)` 能接收什么、失败时怎样**。转换一行只详细写了 `int`。我猜 `float("3.75")` 可以用，结果确实可以；探针显示失败时报 `ValueError: invalid float literal`。文档没有 `parse_float`，也没说 `float` 失败会报错，所以校验浮点输入时只能自己逐字符检查。建议写明 `float` 接受字符串、失败时报 ValueError，并给出校验的写法（或者加一个 `parse_float`）。
3. **`and` / `or` 是否短路**。我写 t1 时担心 `qty == nil or qty <= 0` 不短路（`nil <= 0` 会报 TypeError），就把它拆成了两个 `if`。探针证明它们是短路的。这在配合 `parse_int` 返回 `nil` 的校验里非常常用，建议在第 1 节第 1 条或"更多语义细节"里写一句"`and`/`or` 短路求值"。
4. **区间在起点大于终点时的行为、有没有步长或倒序区间**。文档没写 `3..=1` 是空区间（探针结果是 len 0），也没说能不能倒序遍历。我在螺旋矩阵里倒序走的部分改用了 `while`。建议写明"起点 ≥ 终点时为空区间，没有步长语法，倒序用 `reverse(0..n)` 或 `while`"（`reverse` 能不能用在区间上，我也不确定）。
5. **中文标识符**。文档只说"中文关键字和标识符之间要有空格"，暗示可以用，但没有明说变量名、函数名、结构体名、字段名都可以用中文。建议在关键字表旁边写一句，再给一个全中文的小例子（第 6 节现在没有中文关键字的示例）。

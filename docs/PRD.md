## 1. 背景与目标

设计并实现一门解释型通用脚本语言 **ZYX**，围绕它完成五项交付：

| # | 交付物 | 成功标准 |
|---|---|---|
| 1 | ZYX 语言 + 解释器 | 支持整数、字符串、数组、结构体、输入输出、分支循环、函数；语法有自身特色，不与任何现存语言完全相同 |
| 2 | 黑盒测试集 | 测试脚本用 ZYX 编写，覆盖全部语言功能；一条命令运行全部测试 |
| 3 | 性能测试 | ZYX 性能脚本 + 功能相同的 Python 脚本，给出对比数据与分析 |
| 4 | Agent 开发指南 | 编程 Agent 仅凭文档即可正确编写 ZYX 代码 |
| 5 | 应用程序 | 在 Agent 辅助下用 ZYX 实现一个功能完整、不少于 200 行的程序 |

## 3. 需求一：ZYX 语言设计

完整语义以 [`docs/reference.md`](reference.md) 为准，本节只列要点。

- **数据类型**：`int`（64 位，溢出报错）、`float`、`str`、`bool`、`nil`、`array`、`range`、`fn`、用户结构体
- **控制流**：`if / else if / else`（也是表达式）、`while`、`for x in ...`、`for i, x in ...`、`break`、`continue`、`return`、`match`
- **函数**：具名函数、匿名函数 `fn(x) => x * 2`、闭包、声明提升；最后一个表达式即返回值
- **结构体**：`struct Point { x, y = 0 }`，构造用 `Point(1, 2)` 或 `Point(x: 1)`，方法写在 `impl` 块中
- **输入输出**：`print`、`write`、`input`

### 3.1 特色特性

- 管道运算符 `|>`：`a |> f(b)` 等价于 `f(a, b)`
- 统一调用语法：`a.f(b)` 在 `a` 没有方法 `f` 时等价于 `f(a, b)`
- 字符串插值：`"x = {x + 1}"`
- `match` 支持字面量、区间、`|` 多选、变量绑定和 `if` 守卫
- 块表达式：代码块的最后一个表达式即为其值
- 中文关键字别名，与英文混用（见 [ADR-0003](adr/0003-chinese-keyword-aliases.md)）
- 条件必须是 `bool`，没有隐式真值转换；整数除法向下取整

## 4. 需求一：解释器实现方案

- **语言**：Rust，单个二进制 `zyx`
- **流水线**：源码 → 词法分析 → 语法分析（Pratt 解析表达式）→ AST → 槽位解析（变量编译期定位为槽位编号）→ 执行
- **阶段 A**：AST 树遍历执行，优先保证功能完整
- **阶段 B**：编译为字节码，由栈式 VM 执行，用于性能优化
- **值表示**：`enum Value { Int, Float, Bool, Str(Rc<str>), Array(Rc<RefCell<Vec<Value>>>), Struct(...), Func(...), Nil }`
- **命令行**：`zyx file.zyx` 运行脚本；`--backend tree|vm` 选择后端，测试集须在两个后端上都通过；`zyx` 无参数进入 REPL（可选）

## 5. 需求二：黑盒测试集

- 测试脚本全部用 ZYX 编写，放在 `tests/zyx/`，按功能分文件：字面量、运算符、变量与作用域、分支、循环、函数与闭包、数组、结构体、字符串、输入输出、match、管道、运行时错误
- 断言方式：
  - 脚本内调用 `assert` / `assert_eq`
  - 注释 `# expect: <一行输出>`：逐行比对标准输出
  - 注释 `# expect-error: <错误信息>`：比对错误输出
  - 注释 `# stdin: <输入>`：运行器把内容喂给程序，用于测试 `input`
- 运行器：轻量脚本（Python 或 shell），汇总通过和失败数，失败时打印差异
- 一键运行：`make test`

## 6. 需求三：性能测试

| 用例 | 考察点 |
|---|---|
| `fib(30)` 递归 | 函数调用开销 |
| 千万次循环累加 | 循环与整数运算 |
| 埃氏筛求素数 | 数组读写 |
| 字符串拼接与分割 | 字符串操作 |
| 结构体字段频繁读写 | 结构体访问 |

- 目录 `bench/` 下 ZYX 与 Python 版本一一对应，功能和输出完全一致
- 每个用例运行 5 次取中位数，原始数据写入 `bench/results.md`
- 性能测试报告 `docs/performance-report.md` 包含：测试环境、用例说明、对比表与图、树遍历版 / 字节码 VM 版 / CPython 三方对比、差异原因分析、优化过程记录
- 一键运行：`make bench`

## 7. 需求四：开发指南与 AI 文档

提交物要求两份文档，分别面向人和 AI：

| 文档 | 读者 | 内容 |
|---|---|---|
| `docs/guide.md` 开发指南 | 人 | 构建与安装、第一个程序、按主题的循序渐进教程、调试与报错解读、如何写和运行测试、项目结构 |
| `.claude/skills/zyx/SKILL.md` | 编程 Agent | 带 frontmatter；语法速查表、内置函数签名、与 Python/JS 的差异和易错点（严格布尔条件居首）、运行与测试命令、完整示例程序 |

两者都引用 `docs/reference.md` 作为完整规格。
- **验证方法**：让一个只读过该文档的全新 Agent 编写 3 到 5 个小程序，统计出错点并回补文档，记录迭代过程

## 8. 需求五：应用程序

- 规模：不少于 200 行 ZYX 代码，功能完整
- 选题：终端 2048。输入 `w/a/s/d` 后回车移动，`q` 退出
- 功能：4×4 棋盘、随机生成 2 或 4、合并计分、胜负判定、最高分记录
- 要求覆盖数组、结构体、循环、函数、随机数和输入输出
- 位置：`examples/app/2048.zyx`

### 8.1 开发方式

- 在**全新的** Agent 会话中开发，只提供 `.claude/skills/zyx/SKILL.md`，不带规划阶段的上下文，以检验文档是否足以支撑开发
- 每完成一个功能提交一次

### 8.2 开发记录 `examples/app/DEVLOG.md`

由 Agent 在开发过程中**边做边记**，每完成一个功能或解决一个报错就追加一条，不在结束后补写。每条包含：

| 字段 | 内容 |
|---|---|
| 目标 | 本轮要完成什么 |
| 做法 | 写了什么，查阅了文档的哪一部分 |
| 问题 | 遇到的错误，附原始报错信息 |
| 解决 | 如何修复 |
| 文档反馈 | 文档中不清楚或容易误解的地方，用于回补 `SKILL.md` |

以上要求写入启动开发会话的提示词。

## 11. 风险与应对

| 风险 | 应对 |
|---|---|
| 树遍历版性能明显落后 Python | 槽位解析消除哈希查找；时间允许时升级为字节码 VM；报告中如实分析 |
| 语法设计反复修改导致返工 | M0 先定稿规格与示例，之后的改动同步更新测试 |
| Rust 所有权与引用循环处理复杂 | 用 `Rc<RefCell>` 表示共享可变值，暂不处理循环引用回收 |
| Agent 写 ZYX 时按 Python 习惯出错 | 在 SKILL.md 中单列易错点，并用验证结果迭代 |
| 应用需要实时按键输入 | 选题限定为逐行输入即可完成的程序 |

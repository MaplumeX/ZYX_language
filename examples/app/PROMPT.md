# 开发任务：用 ZYX 实现终端 2048

> 这是启动编程 Agent 开发会话时使用的任务说明（PRD 第 8 节）。开发者 Agent 只凭 `.claude/skills/zyx/SKILL.md` 了解 ZYX 语言。

## 产出

- `examples/app/2048.zyx`：游戏源代码，**不少于 200 行有效代码**（不含空行和纯注释行）。
- `examples/app/DEVLOG.md`：开发日志，要求见下文。

## 功能需求

1. **棋盘**：4×4。开局随机放置 2 个方块；每个新方块 90% 概率是 2，10% 概率是 4。
2. **操作**：每次读入一行命令并回车：`w` 上、`a` 左、`s` 下、`d` 右，大小写都可以；`r` 重新开始，`h` 显示帮助，`q` 退出。
3. **移动与合并**：遵循标准 2048 规则。同一次移动中，一个方块最多合并一次，比如 `[2, 2, 2, 2]` 左移得到 `[4, 4, 0, 0]`，`[4, 4, 8, 0]` 左移得到 `[8, 8, 0, 0]`。只有棋盘真的发生变化，才生成新方块并计为一步；无效移动要给出提示。
4. **计分**：每次合并，得分加上合并后的数值。界面显示当前分数、本次运行中的最高分（重新开始后保留）和步数。
5. **胜负**：首次出现 2048 时提示胜利，并询问是否继续（`y` 继续游戏，其他输入回到新局）。没有任何可行移动时提示游戏结束，显示最终分数，等待 `r` 重新开始或 `q` 退出。
6. **显示**：每一步之后重新打印棋盘，数字右对齐、格子宽度一致，空格用 `.` 表示。
7. **健壮性**：未知命令要提示并继续。输入结束（`input()` 返回 `nil`）时正常退出，打印最终分数。
8. **可测试性**：
   - 核心逻辑写成独立函数，至少包括：单行合并、四个方向的移动、判断是否还能移动、生成新方块。
   - 首行命令为 `test` 时进入自测模式，用 `assert_eq` 检查核心函数，覆盖上面两个合并示例、四个方向、无路可走的判定等，全部通过后输出 `self-test passed` 并退出。
   - 首行命令为 `seed N` 时用 `seed(N)` 固定随机数，便于复现一局游戏。
9. **代码组织**：用结构体表示游戏状态，用 `impl` 实现方法，至少用到一次 `match` 和一次管道 `|>`。

## 开发方式

- 关于 ZYX 只阅读 `.claude/skills/zyx/SKILL.md`（也可以通过 zyx 技能加载它）。不要阅读 `docs/`、`src/`、`tests/`、`bench/` 或其他已有的 `.zyx` 文件。
- 增量开发：先实现并测试核心逻辑，再做交互界面，最后完善胜负判定和边界情况。
- 每完成一个功能就提交一次：只能 `git add examples/app/`，提交信息以 `app(2048): ` 开头。不要改动 `examples/app/` 以外的文件，不要推送。

## 开发日志 `DEVLOG.md` 的要求

**边做边记**：每完成一个功能，或解决一个报错，立即追加一条，不在结束后补写。每条日志使用以下格式：

```markdown
### N. 标题（对应的提交）

- **目标**：本轮要完成什么
- **做法**：写了什么，查阅了 SKILL.md 的哪一部分
- **问题**：遇到的错误，附原始报错信息或错误输出；没有问题就写"无"
- **解决**：如何修复
- **文档反馈**：SKILL.md 中不清楚或容易误解的地方；没有就写"无"
```

日志末尾写一节总结：
- 总共几条日志、几次提交；
- 第一次运行就正确的功能占比；
- 最终代码行数及统计方法；
- 对 SKILL.md 的整体评价。
